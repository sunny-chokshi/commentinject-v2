# CommentInject v2 for promptfoo

This folder runs CommentInject v2 as a [promptfoo](https://github.com/promptfoo/promptfoo) eval. `commentinject-code-review/` follows promptfoo's upstream `examples/<name>/` layout: a `README.md` that starts with `# folder-name (Human Readable Name)`, a `promptfooconfig.yaml` with the schema comment, `file://` references, and instructions using `npx promptfoo@latest init --example`. It can be copied into `promptfoo/examples/` unchanged. The scripts beside it are local tooling and are not part of the example.

| Path | What it is |
|---|---|
| `commentinject-code-review/promptfooconfig.yaml` | Eval config: Ollama `/api/generate` provider (temperature 0, seed 0, as in `scripts/run.py`), `javascript` assertion, `tests: file://tests.jsonl` |
| `commentinject-code-review/review_prompt.j2` | `scripts/common.py:REVIEW_PROMPT` with `{code}` replaced by `{{code}}`. It is generated by the exporter. |
| `commentinject-code-review/verdict.js` | A port of `parse_verdict` (negation-aware v2 parser). The test passes when the verdict matches `vars.label`. It also returns `namedScores.flagged` and `namedScores.unparsed`. |
| `commentinject-code-review/tests.jsonl` | All 840 cases, generated. `vars` holds `code`, `case_id` and `label`. `metadata` holds every case field, for `--filter-metadata`. |
| `export_tests.py` | Builds `tests.jsonl` and `review_prompt.j2` from `data/cases.jsonl`. Subset flags: `--pairs`, `--conditions`, `--strategies`, `--variants`, `--limit`, `--out`. |
| `to_predictions_csv.py` | Turns promptfoo's `-o results.json` into a `case_id,flagged,model,parse_mode,response` CSV for `scripts/score_predictions.py`. It re-parses every reply in Python and stops if verdict.js disagrees. |
| `tests/test_promptfoo_integration.py` | Pytest suite, with no model calls |

## Run

```bash
# from the repo root
python3 -I integrations/promptfoo/export_tests.py                        # regenerate the 840 tests
python3 -I integrations/promptfoo/export_tests.py --pairs V24 --out /tmp/pf/tests_V24.jsonl --prompt-out ''

export PROMPTFOO_DISABLE_TELEMETRY=1 PROMPTFOO_DISABLE_UPDATE=1
cd integrations/promptfoo/commentinject-code-review
npx promptfoo@0.126.0 eval -t /tmp/pf/tests_V24.jsonl -j 1 --no-cache --no-write --no-share -o /tmp/pf/out.json
# or, on the full file: npx promptfoo@0.126.0 eval --filter-metadata pair_id=V24 -j 1 ...
cd -
python3 -I integrations/promptfoo/to_predictions_csv.py /tmp/pf/out.json /tmp/pf/preds.csv
python3 -I scripts/score_predictions.py /tmp/pf/preds.csv /tmp/pf/scored/
```

promptfoo exits with code 100 when some assertions fail. That is expected here, because failures are the benchmark's misses and false alarms.

## Test

```bash
python -m pytest -q -p no:cacheprovider integrations/promptfoo/tests          # needs node on PATH
PROMPTFOO_BIN=/path/to/node_modules/.bin/promptfoo python -m pytest -q -p no:cacheprovider integrations/promptfoo/tests
```

With `PROMPTFOO_BIN` set, the suite also runs all 840 tests through promptfoo's `echo` provider. It checks that every rendered prompt equals `REVIEW_PROMPT.format(code=...)` byte for byte. The verdict.js parity test runs every stored model reply under `results/` through both parsers.

Tested versions and results are in `integrations/LOCAL_TEST_LOG.md`.
